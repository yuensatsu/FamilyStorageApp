# 初心者向け開発工程まとめ

AIを使う場合でも、開発の基本的な流れは大きく変わりません。
違うのは、設計の整理やコードの下書きをAIに手伝わせられる点です。

まずは紙やメモに書き出してから、AIに「次に作る小さい範囲」を渡すと進めやすくなります。

## 共通の考え方

開発は、いきなりコードを書くのではなく、次の順番で進めます。

```text
目的を決める
↓
必要な機能を決める
↓
画面や操作を考える
↓
保存するデータを考える
↓
小さく作る
↓
動かして確認する
↓
直す
↓
人に使ってもらう、または遊んでもらう
↓
改善する
```

大事なのは、最初から完成形を作ろうとしないことです。
まずは「1画面、1操作、1データ」または「1つの遊びのループ」に絞ります。

## ゲーム制作の開発順序

### 1. 企画・目的決め

どんな体験を作りたいかを決めます。

紙に書く項目:

```text
ゲーム名:
ジャンル:
プレイヤーに感じてほしいこと:
プレイヤーがすること:
一番気持ちいい瞬間:
```

例:

```text
ゲーム名: 30秒サバイバル
ジャンル: 避けゲー
プレイヤーに感じてほしいこと: ギリギリで避ける緊張感
プレイヤーがすること: 左右に動いて敵を避ける
一番気持ちいい瞬間: 敵をギリギリで避けた時
```

### 2. 要件定義

何ができれば最初の完成とみなすかを決めます。

紙に書く項目:

```text
できること:
- （ここに記入）

成功条件:
- （ここに記入）

失敗条件:
- （ここに記入）

今回は作らないもの:
- （ここに記入）
```

例:

```text
できること:
- プレイヤーが左右に動ける
- 敵が上から落ちてくる
- 敵に当たるとゲームオーバーになる

成功条件:
- 30秒生き残る

失敗条件:
- 敵に当たる

今回は作らないもの:
- アイテム
- ステージ選択
- オンラインランキング
```

### 3. 画面・操作設計

どんな画面で、どう操作するかを決めます。

紙に書く項目:

```text
画面:
- タイトル
- プレイ画面
- ゲームオーバー画面

操作:
- （ここに記入）

画面に表示するもの:
- （ここに記入）
```

### 4. データ設計

ゲーム内で扱う情報を決めます。

紙に書く項目:

```text
プレイヤー:
- 位置
- 移動速度

敵:
- 位置
- 落下速度

ゲーム状態:
- 残り時間
- スコア
- プレイ中かどうか
```

### 5. 設計

処理の役割を分けます。

よくある分け方:

```text
Input: 入力
Player: プレイヤー処理
Enemy: 敵処理
GameManager: ゲーム状態、勝敗判定
UI: 画面表示
SaveData: セーブデータ
```

### 6. 実装

まずは最小の遊びだけ作ります。

最初に作る範囲の例:

```text
今回は「プレイヤーが動いて、敵に当たるとゲームオーバー」まで作る。
スコア、演出、音、複数ステージは後回し。
```

### 7. テスト

実際に遊んで確認します。

確認項目:

```text
正常系:
- プレイヤーが操作できる
- 敵が落ちてくる
- 敵に当たるとゲームオーバーになる

異常系:
- 画面外に出ない
- ゲームオーバー後に操作が暴走しない
- リトライできる

面白さ:
- もう一回遊びたい理由がある
- 失敗した時に納得感がある
- 上手くなった感覚がある
```

### 8. 修正・改善

気づいた問題を1つずつ直します。

例:

```text
今回直すこと:
- 敵の落下速度が速すぎるので少し遅くする

今回はまだ直さないこと:
- 背景
- BGM
- キャラクター画像
```

### 9. 公開・プレイしてもらう

自分以外の人に触ってもらいます。

聞くこと:

```text
何をするゲームか分かったか:
難しすぎなかったか:
もう一回遊びたいと思ったか:
分かりにくかったところ:
```

## アプリ制作の開発順序

### 1. 企画・目的決め

誰のどんな困りごとを解決するかを決めます。

紙に書く項目:

```text
アプリ名:
使う人:
困っていること:
このアプリで解決したいこと:
```

例:

```text
アプリ名: 家の物管理アプリ
使う人: 家族
困っていること: 物がどこにあるか分からない
このアプリで解決したいこと: 物の名前で収納場所を探せるようにする
```

### 2. 要件定義

何ができれば便利になるかを決めます。

紙に書く項目:

```text
できること:
- （ここに記入）

入力するもの:
- （ここに記入）

保存するもの:
- （ここに記入）

今回は作らないもの:
- （ここに記入）
```

例:

```text
できること:
- 物を登録できる
- 物の一覧を見られる
- 物の名前で検索できる

入力するもの:
- 物の名前
- 収納場所
- メモ

保存するもの:
- 物の名前
- 収納場所
- メモ
- 登録日

今回は作らないもの:
- ログイン
- 家族共有
- 写真登録
- 通知
```

### 3. 画面設計

必要な画面を決めます。

紙に書く項目:

```text
画面:
- ホーム画面
- 一覧画面
- 登録画面
- 詳細画面

最初に作る画面:
- （ここに記入）
```

最初は手描きで十分です。

```text
[検索欄]

- はさみ    リビングの棚
- 電池      玄関の引き出し
- 通帳      寝室の棚

[追加ボタン]
```

### 4. データ設計

アプリが保存する情報の形を決めます。

紙に書く項目:

```text
物:
- 名前
- カテゴリ
- 収納場所
- メモ
- 登録日

収納場所:
- 場所名
- 部屋名
```

ここを先に考えると、画面や処理が整理しやすくなります。

### 5. 設計

処理の役割を分けます。

Webアプリでよくある分け方:

```text
Controller: 画面やリクエストを受ける
Service: ルールや処理を書く
Repository: データベースとやり取りする
Entity/Model: データの形
Form: 画面入力の受け皿
```

小さなアプリなら、最初は次の3つだけ意識しても十分です。

```text
画面
処理
データ保存
```

### 6. 実装

まずは1機能だけ作ります。

最初に作る範囲の例:

```text
今回は「物を登録して一覧に表示する」だけ作る。
検索、写真、編集、削除、ログインは後回し。
```

### 7. テスト

正しく動くか確認します。

確認項目:

```text
正常系:
- 名前と収納場所を入力したら登録できる
- 登録した物が一覧に表示される

異常系:
- 名前が空欄なら登録できない
- データが0件でも画面が壊れない
- 長すぎる文字を入れても壊れない
```

### 8. 修正・改善

一番困る問題から直します。

例:

```text
今回直すこと:
- 空欄で登録できてしまう問題を直す

今回はまだ直さないこと:
- デザイン
- 写真登録
- 家族共有
```

### 9. リリース・使ってもらう

人に使ってもらえる状態にします。

聞くこと:

```text
何のためのアプリか分かったか:
登録は迷わずできたか:
一覧は見やすかったか:
次に欲しい機能:
```

## AIに渡す時の形

AIには、ゲーム全体やアプリ全体を丸投げせず、次に作る小さい範囲だけ渡します。

```text
この全体案のうち、今回は最小機能だけ作りたいです。

目的:

今回作る範囲:

入力:

表示:

保存するデータ:

成功条件:

失敗条件、またはエラー条件:

今回は作らないもの:

依頼:
- 必要なファイル構成を提案してください
- 実装順序を出してください
- 最小実装にしてください
- 動作確認手順を出してください
```

初心者のうちは、AIにコードを書かせる前に、まずこの形で整理してもらうのがおすすめです。
